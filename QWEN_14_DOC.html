PHASE 1 · DOCUMENT 02

Implementation Constitution

Hukum mengikat yang diterjemahkan dari konstitusi beku ke dalam kontrak implementasi Native-HTML. Setiap hukum punya bentuk operasional yang dapat diuji oleh Governance (Constitution Validation). Pelanggaran = BUILD STOP.

1.1 Identitas Sistem (bukan trading bot)

ST-LMS diimplementasikan sebagai Market Geometry Intelligence Operating System native-HTML. Ia adalah laboratorium observasi, perilaku, simulasi, replay, pengetahuan, governance, prediksi-empiris, dan audit — bukan trading bot, scanner, maupun AI assistant. Eksekusi trade (paper/live) adalah Consumer opsional; Core (BOOT→Governance) wajib hidup & belajar walau Consumer dihapus (Trade is Optional, Learning is Mandatory).

1.2 Hukum Implementasi Mengikat

LAW-01
Determinisme Mutlak
Tidak ada Date.now()/random bebas di logika; waktu dari candle; PRNG = Mulberry32 seeded ts+config_version; tie-break deterministik.
LAW-02
Kejujuran Data (No-Fake)
Tak terhitung = NULL+status (INSUFFICIENT_DATA/WARMUP/PROVISIONAL); wave<6 = PENDING_WAVE; OI kosong ≠ 5000.
LAW-03
Immutability Card
Setiap fakta = card beku + checksum; “update” = card versi baru ber-lineage.
LAW-04
Aliran Unidirectional
Data→Truth→Structure→Evidence→Clone→Sim→Knowledge→Consumer; Knowledge/Consumer tak menulis Core.
LAW-05
No-Reduction
Dilarang mereduksi kecerdasan ke satu skor/sinyal; MIB = pemahaman, bukan BUY/SELL.
LAW-06
Card Sharing
Truth/Structure/Evidence dihitung 1×/candle, di-share ke 3 clone; clone tak menghitung geometri.
LAW-07
1 Candle = 3 Knowledge
LONG/SHORT/GRID tiap menulis observasi per closed candle, walau no-trade.
LAW-08
Geometry = Foundation
Indikator bukan decision-maker; dipakai sesuai Authority Matrix saja.
LAW-09
W%R Terbatas
W%R/Vel/Acc = exit/early-wrong/CERMIN; dilarang entry; tak masuk vektor Oracle.
LAW-10
Fee Berlapis Jujur
0.7% = REQUIRED_MOVE; fee murni 0.04–0.10%; result=WIN hanya bila net>0; adverse-first.
LAW-11
HUKUM CAGE
2 dinding valid ⇔ kompresi; 1 dinding ⇔ trend (jarak seberang = NULL).
LAW-12
Human Approval + Bounded
Darwin mengusulkan; WASIT menyaring; manusia memutus; nilai luar rentang = auto-reject.
LAW-13
Native-HTML Offline
Tanpa backend/DB-server/framework; IndexedDB+Worker+CompressionStream; replayable offline.
LAW-14
Sample-Gated
Statistik/knowledge di bawah ambang sample = BELUM_CUKUP, bukan keyakinan.
LAW-15
Prediction = Empiris
Probabilitas = frekuensi bersyarat (Academy) + similarity (Oracle); bukan forecast model.

1.3 Platform Binding (bukan redesign filosofi)

translasi platform — setia pada konstitusi inti

Konstitusi inti tidak mengikat bahasa; konstitusi implementasi mengikat platform = browser native. Maka translasi yang wajib & setia: SQLite→IndexedDB (append-only card store); ProcessPool→Web Worker (job dingin: Academy/Oracle/Darwin/WASIT); file LZMA→CompressionStream+IndexedDB blob; float→BigInt integer-tick per-aset (representasi panas) + canonical string (audit); PRNG Mulberry32 sudah JS-native. Ini PLATFORM-BINDING, bukan perubahan filosofi/authority/lifecycle.

PHASE 3 · DOCUMENT 04

Workspace Architecture

Struktur “ruang kerja” Native-HTML: bagaimana artefak, state, dan cache ditata di browser tanpa backend. Ini padanan tiered storage konstitusi, diterjemahkan ke IndexedDB + Storage API + memory.

3.1 Lapisan Penyimpanan (tiered, browser-native)

TierMediaIsiKebijakan
L1 HotJS memory (per simbol)state builder, posisi clone, candle kini, grid_fillsbeberapa KB; dibuang saat idle
L2 WarmIndexedDB warmenriched 7h, materialized rapor, config aktifakses cepat panel
L3 ColdIndexedDB cold + blobcard history >7h, marker, snapshotCompressionStream saat tulis
L4 ArchiveIndexedDB archive / exportrun lama, fixture mentah terkompresiexport .json.gz / .lzma
L5 Evict—>retensihapus deterministik

3.2 Object Stores IndexedDB

cards (PK=id, idx: type+ts, config+ts), config_state, checkpoints (per simbol: last_processed_1m + indicator state), governance (proposals+decisions), audit_log, runs. Semua write melalui satu writer serial di main thread (worker hanya compute & postMessage hasil) → nol race, meniru “persist serial proses utama”.

3.3 Workspace Manager & Checkpoint

  • Workspace = kumpulan object store + config_version aktif + cursor replay; bisa di-export/import utuh (offline portabel).
  • Checkpoint disimpan tiap N candle & saat pause: memungkinkan resume pasca-tab-close tanpa recompute dari nol (memanfaatkan CPU-idle→recompute hanya hot-window 3h bila checkpoint absen).
  • Eviction berbasis usia data market + last-logical-access (bukan wall-clock) → menjaga determinisme replay.
PHASE 4 · DOCUMENT 05

Runtime Architecture

Topologi proses browser: mana yang hot monolith (main thread, sekuensial per simbol), mana yang worker dingin (paralel, mati setelah selesai), dan mengapa — agar determinisme & integritas store terjaga.

4.1 Pembagian Thread

ThreadTugasAlasan
Main (hot)BOOT, server-less event loop, Truth/Structure/Evidence/Clone per-candle sekuensial, writer IndexedDB serial, UI render, clock WIBstate EMA/ATR/posisi kontigu; writer tunggal = nol race
Worker·Databootstrap batch, derived-TF agregasi, gap-repair (I/O-bound via fetch fixture)lepas dari UI; mati setelah batch
Worker·KnowledgeAcademy batch, Oracle similarity, Darwin proposal, LibrarianCPU-bound jarang; RAM kembali saat mati
Worker·BenchmarkWASIT walk-forward: base & candidate paralel (2 sub-task)memanfaatkan multi-core; deterministik (seed)
Worker·Replayreplay panjang per simbol (paralel antar-simbol)independen antar-simbol
hukum runtime — yang TIDAK boleh diparalelkan

Truth/Structure/Evidence/Clone per-candle untuk satu simbol wajib sekuensial di main (state kontigu). Memaralelkannya per-candle = memutus kontinuitas EMA/ATR atau memaksa baca-tulis checkpoint per candle (lebih mahal dari komputasinya). Paralel hanya: antar-simbol & base-vs-candidate & batch knowledge. Worker dilarang menulis IndexedDB langsung — kirim hasil via postMessage, main yang persist.

4.2 Resource Governor (browser)

Membaca tekanan via performance.memory (bila tersedia) + heuristik ukuran store; threshold 70/85/95%: 70→flush warm+gc+kill worker idle; 85→pause spawn worker baru (hot lanjut); 95→degraded (skip evidence opsional, tolak entry baru). Tidak ada setInterval pemutar candle di idle — sistem digerakkan permintaan/replay (hemat saat tab pasif).

PHASE 8 · DOCUMENT 09

Simulation Architecture

Simulator = first-class citizen. Ia mengeksekusi niat clone terhadap candle & menulis marker after-fee (adverse-first). Clone tidak menghitung PnL sendiri.

8.1 Jenis Simulasi Wajib

  • Historical Simulation — replay fixture/IndexedDB deterministik.
  • Live Simulation — feed 1m (fetch/WS bila online; fallback fixture offline); provisional≠final.
  • Strategy Simulation — satu clone diisolasi untuk studi.
  • Clone Simulation — 3 clone bersamaan, ledger terisolasi, snapshot bersama.

8.2 Hukum Eksekusi

SIM-01
Adverse-First
SL & TP se-candle → SL menang (konservatif, jujur).
SIM-02
Fee Berlapis
net = gross − fee_murni(taker,discount) − slip_seeded − safety; WIN hanya net>0.
SIM-03
Entry = Close
entry pada close candle FINAL; provisional ditolak.
SIM-04
MAE/MFE
dilacak per posisi → bahan kalibrasi SL/TP (CERMIN-EXIT).
SIM-05
Persist Serial
worker kirim hasil; main yang tulis IndexedDB → nol race.

10.2 Workflow Proposal (3 rem)

  4. Approve → config_version baru pada boundary deterministik + audit; rollback = tunjuk version lama.
